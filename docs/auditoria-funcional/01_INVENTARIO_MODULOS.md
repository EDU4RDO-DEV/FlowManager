# Inventario de módulos y submódulos

## Criterio y estado

El inventario refleja carpetas, pantallas, rutas, servicios y modelos localizados en los archivos del repositorio. **Confirmado** significa que existe evidencia técnica de una capa funcional; no afirma que el flujo esté completo ni que satisfaga requisitos de negocio. **Parcial / por verificar** indica que se encontró una pantalla o estructura sin evidencia equivalente de API/proceso, o que su relación funcional no está demostrada.

Se agrupan las áreas en 14 dominios funcionales con evidencia backend/API y una pantalla de producción pendiente de verificación. No se incluyen reportes, dashboards, indicadores ni visualizaciones analíticas en las auditorías especializadas.

Las ubicaciones centrales son [backend/src/routes/](../../backend/src/routes/), [backend/src/controllers/](../../backend/src/controllers/), [backend/src/services/](../../backend/src/services/), [backend/src/validators/](../../backend/src/validators/), [frontend/app/](../../frontend/app/) y [frontend/services/](../../frontend/services/). La API completa está montada en [backend/src/app.ts](../../backend/src/app.ts).

## Superficies API montadas

Los 26 routers son: `/api/auth`, `/api/adjustments`, `/api/clients`, `/api/client-catalog`, `/api/company`, `/api/commercial-rules`, `/api/credits`, `/api/dashboard`, `/api/employees`, `/api/envases`, `/api/inventory-log`, `/api/logistics` (dos routers), `/api/notifications`, `/api/planilla`, `/api/products`, `/api/product-structure`, `/api/compras`, `/api/providers`, `/api/calidad`, `/api/reports`, `/api/roles`, `/api/ventas`, `/api/sessions`, `/api/talonarios` y `/api/users`. Todos los routers salvo autenticación quedan montados tras `requireAuth`; las rutas interiores aplican permisos por módulo/acción según sus definiciones.

La especificación exacta de operaciones está en cada archivo `backend/src/routes/*.routes.ts`; los principales subflujos visibles incluyen pago/anulación de pago, anulación/restauración, carga de imágenes, talonarios, sesiones de ruta, mantenimiento, reglas comerciales y validación de calidad.

## Modelo de datos

El esquema [backend/prisma/schema.prisma](../../backend/prisma/schema.prisma) contiene 42 modelos. Los estados/categorías aparecen en buena medida como valores string en servicios/validadores y no debe presumirse que cada valor sea un catálogo persistido. Modelos principales, agrupados por evidencia:

- **Identidad:** `Usuario`, `Sesion`, `Rol`, `ModuloSistema`, `AccionSistema`, `RolPermiso`, `Entidad`, `Empleado`.
- **Comercial:** `Cliente`, `TipoCliente`, `ClienteCondicionCredito`, `TipoCredito`, `ReglaPrecioCliente`, `ReglaBonificacion`, `Venta`, `DetalleVenta`, `PagoVenta`, `Talonario`, `CuentaPorCobrar`.
- **Inventario/compras:** `InventarioItem`, `AjusteInventario`, `BitacoraInventario`, `EstructuraProducto`, `Compra`, `DetalleCompra`, `DetalleGasto`, `Proveedor`.
- **Operación de ruta/envases:** `Ruta`, `RutaSesion`, `Vehiculo`, `GastoVehiculo`, `MantenimientoVehiculo`, `MovimientoEnvase`, `EnvaseClienteSaldo`.
- **Personal/calidad/empresa:** `ConfiguracionComision`, `ReglaComision`, `PlanillaMensual`, `PlanillaDetalleComision`, `PlanillaDetalleAjuste`, `ControlCalidadAgua`, `Empresa`.
- **Reportes excluidos:** también existe `ReporteHistorial`.

Esta agrupación no es un análisis campo por campo; las relaciones concretas se amplían en [03_MAPA_DEPENDENCIAS.md](./03_MAPA_DEPENDENCIAS.md).
